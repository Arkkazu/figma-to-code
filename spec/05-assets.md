# 05. アセットのエクスポートと最適化（Q-05）

- 設問: 画像・SVG・アイコンをどの形式でエクスポートし最適化するか？
- 状態: 合格（kazu の確定承認待ち。批評記録は STATE.md [14][32]）

## 方針

Figma実装プレイブック `rules/figma-image-export.md`（2026-06-27 制定の恒久ルール）を**上位規則として継承**し、本節はそれと矛盾しない範囲で形式選択・解像度・命名・配置・最適化を確定する。取得手段と取得時の限界は Q-01（spec/01-extraction.md §2 download_assets）に従う。

根拠の凡例は Q-01 と同じ:【公式】【実測:MyBrain】【実測:スキーマ】【仮説】

## 1. 形式選択基準（アセット種別 → 形式）

| アセット種別 | 取得形式 | 配信形式 | 根拠 |
|---|---|---|---|
| アイコン・ロゴ・矢印・線画・単色/少色の図形・拡縮するUI素材 | SVG（`defaultFormat: svg`） | SVG | 【実測:MyBrain figma-image-export.md】原則SVG。PC用でもSVG化できる素材は倍率書き出しよりSVG優先 |
| 写真・複雑なグラデーション・ノイズ・質感・ビットマップ前提の背景/イラスト | **raw（元画像）優先**。rawが無い場合は png 書き出し | WebP を既定とし、ビルド工程で変換（品質の初期値と昇格条件は §4-1） | 【実測:MyBrain】raw優先は Q-01 §2。`download_assets` の書き出し format に **webp は無い**（png/jpg/svg/pdf のみ)【実測:スキーマ】ため、配信用 WebP はビルドで生成する |
| 透過が仕様のラスター | raw 優先の PNG。取得後にαチャンネルの透明ピクセル数を実測 | **WebP（アルファ付き）を既定**とする。PNG を使うのは次のいずれかのみ: ①案件の対応ブラウザ要件に WebP 非対応ブラウザが含まれる ②WebP 変換後のα実測で透過が劣化（半透明の階調潰れ等）した場合 | 【実測:MyBrain figma-image-export.md / mistakes.md 2026-06-30】白背景混入の既知事例あり。選択条件は本仕様の規定 |
| アニメーション画像（GIF等の raw） | raw のまま | 動画（`<video>`）や CSS アニメーションでの代替をデザイナーに確認してから決定 | 本仕様の規定（GIFは容量効率が悪いため） |
| ベクター由来だが色数・効果が複雑でSVGが肥大するもの | SVG と png 書き出しの両方を取得し比較 | 同表示寸法での実ファイルサイズが小さい方（同等なら SVG） | 本仕様の規定 |

- 実体フォーマットの確認: 取得したファイルはレスポンスの実フォーマット（`format` フィールド【実測:スキーマ】）を確認し、実体に合う拡張子で保存する。拡張子だけ `.png` に統一する保存は禁止【実測:MyBrain figma-image-export.md】。
- スクリーンショットの切り抜きを正式アセットにしない（asset 取得不可＋kazu の明示許可がある場合のみ例外）【実測:MyBrain figma-image-export.md】。

## 2. 解像度

- ラスターの標準書き出し倍率: **PC用 1.5倍 / SP専用 2倍**【実測:MyBrain figma-image-export.md】。`defaultScale` で指定する（許容範囲: 最小 0.01・最大 4【実測:スキーマ】）。
- 基準となる表示サイズは「表示CSSサイズ」（Figma上のノード寸法ではなく、実装でその画像が表示される最大CSSピクセル寸法）。表示CSSサイズ×倍率が実画像寸法を上回らないこと。
- export 設定なしのレンダーは長辺約4096pxまで【公式・Q-01 出典2】。超える大判はFigma側の export 設定を依頼するか、分割を検討する。
- 解像度不足は拡大生成・アップスケールで補わない。「Figma側で高解像度元画像が必要」としてデザイナー/kazu に報告する【実測:MyBrain figma-image-export.md】。

## 3. 命名・配置規則

案件側 `MyBrain/rules/` に規約がある場合はそれを優先する。無い場合の既定を以下とする。

- 命名: 小文字ケバブケースで `{セクション}-{用途}.{実体拡張子}`（例: `hero-illustration.svg`、`voice-photo-01.webp`）。用途が分かる名前にし、`image.png` / `bg.png` / `asset.png` 等の汎用名を禁止【実測:MyBrain figma-image-export.md】。
- 倍率書き出しのラスターは元寸のCSSサイズで使う前提のため倍率サフィックスを付けない。同一画像を複数解像度で持つ場合のみ `-2x` 等のサフィックスを付ける（本仕様の規定）。
- 配置: `assets/images/{ページ}/` を既定とする（トップページは `assets/images/home/`【実測:MyBrain figma-image-export.md】）。ページ横断で使う共通素材は `assets/images/common/`。
- SVGの使い分け: CSS で色を変える必要があるアイコンはインラインSVG、それ以外は `<img>` または背景画像（本仕様の規定）。
- 既存画像がある場合は、ファイルサイズ・画像寸法・hash で Figma asset と照合し、完全一致なら既存を使い、不一致なら Figma 由来と分かる名前で保存して参照を更新する【実測:MyBrain figma-image-export.md】。

## 4. 最適化と読込

### 4-1. WebP 変換の品質規定

- 初期値: 品質 80（非可逆）で変換する（初期値は【仮説】であり、kazu の確定承認時に見直してよい）。
- 昇格条件: Q-09 の視覚照合で当該画像に差分が検出された場合、品質 90 → ロスレスの順に上げて再照合する。グラデーションの縞（バンディング）・透過の階調潰れが目視または α実測で確認された場合もロスレスへ昇格する。
- 例外: ロスレス WebP が元 PNG よりファイルサイズが大きくなる場合は元形式のまま配信する。
- 適用した品質と昇格理由はアセット一覧（§4-2 のセット照合項目）に記録する。

### 4-2. 最適化・照合

- SVG: svgo 等で最適化する。ただし `viewBox` は保持し、アクセシビリティ用の `title` / `desc` を削除しない（本仕様の規定）。
- ラスター: WebP 変換後もファイルサイズを確認する。修正・差し替え時は `alt`・実フォーマット/拡張子・表示CSSサイズ・書き出し倍率・ファイルサイズをセットで照合してから完了報告する【実測:MyBrain mistakes.md 2026-06-30】。
- 遅延読込: ファーストビュー外の画像は `loading="lazy"` を既定とする。ただし無限スクロール・マーキー・横流れバナー等「見えている領域に常時描画が必要」な文脈では画面内進入後の描画遅延が既知の不具合であり、`loading="eager"` 等でも防げない場合がある。この場合はスプライト画像を背景にして `background-position` を動かす方式を優先する【実測:MyBrain corrections.md 2026-07-06】。
- 背景画像は画像ファイル単体でなく Figma のレイヤー構造（opacity・blend mode・overlay・gradient・トリミング）まで確認し、CSS の合成方法が違えばデザイン差分として扱う【実測:MyBrain figma-image-export.md】。照合は Q-09 の検証項目に含める。
